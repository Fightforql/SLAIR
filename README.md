# SLAIR: All-in-One Image Restoration with Latent Space Separation and Deterministic Transport

The PyTorch implementation of **SLAIR**, an all-in-one image restoration framework that restores images in a separated latent space with deterministic transport.

**Pretrained weights and latent statistics are available at [ash1313/SLAIR](https://huggingface.co/ash1313/SLAIR).**

## Abstract

We propose SLAIR, an all-in-one image restoration framework integrating latent space separation and deterministic transport. We introduce a latent-space separation approach that ensures stable, distinct representations of degraded and clean images, facilitating effective flow matching. By learning continuous transport flow in a latent space via an ordinary differential equation (ODE), our method enables deterministic restoration without relying on degradation labels or stochastic sampling. While the restoration is performed in the latent space, a high-frequency refinement module is introduced into the latent decoder to handle detail distortion during decoding. Experiments demonstrate that SLAIR outperforms existing approaches in terms of both perceptual quality and computational efficiency, making it a robust solution for scalable, degradation-agnostic image restoration.

## Method

SLAIR separates degraded and clean images in the VAE latent space, then learns a deterministic ODE transport flow between the two latent distributions. The pipeline contains three main training stages:

1. Train the VAE/tokenizer.
2. Extract paired latents and train the DiT transport model.
3. Train the high-frequency refinement decoder.

The method overview is also embedded above as [`assets/method.png`](assets/method.png).

```bash
conda create -n slair python=3.10 -y
conda activate slair

# Install PyTorch according to your CUDA version.

pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

pip install -r requirements.txt
pip install -r vavae/vavae_requirements.txt

# Configure accelerate before distributed extraction/training/inference.
```

- `vavae/configs/train.yaml`
- `tokenizer/configs/vavae_f16d32.yaml`
- `configs/lightningdit_xl_vavae_f16d32.yaml`
- `configs/train.yaml`

## Pretrained Weights and Latent Statistics

Pretrained files are available at [ash1313/SLAIR](https://huggingface.co/ash1313/SLAIR). Download them into a local directory such as `pretrained/` under the repository root:

```bash
pip install -U huggingface_hub
mkdir -p pretrained
huggingface-cli download ash1313/SLAIR --local-dir pretrained
```

After downloading, the recommended local layout is:

```text
SLAIR/
|-- pretrained/
|   |-- vavae.ckpt              # shared VAE/tokenizer checkpoint
|   `-- setting-ii/
|       |-- 0100000.pt          # Setting-II DiT/transport checkpoint
|       |-- decoder.pt          # Setting-II decoder/fusion checkpoint
|       |-- 5task-train.pt      # Setting-II train latent mean/std
|       `-- 5task-val.pt        # Setting-II validation latent mean/std
```

Setting-I weights are not released yet.

Set the VAE checkpoint in `tokenizer/configs/vavae_f16d32.yaml`:

```yaml
ckpt_path: pretrained/vavae.ckpt
```

Set the Setting-II DiT checkpoint and decoder/fusion checkpoint in `configs/lightningdit_xl_vavae_f16d32.yaml`:

```yaml
ckpt_path: pretrained/setting-ii/0100000.pt

vae:
  fusion_ckpt_path: pretrained/setting-ii/decoder.pt
```

Set the latent statistics used by online DiT/decoder training in `configs/train.yaml`:

Latent normalization requires a statistics file. In `configs/train.yaml`, set:

```yaml
data:
  csv_path: /path/to/5-task_train.csv
  stats_path: pretrained/setting-ii/5task-train.pt

valid_data:
  csv_path: /path/to/5-task_val.csv
  stats_path: pretrained/setting-ii/5task-val.pt
```

The stats files contain the latent `mean` and `std` used when `latent_norm: true`. The released `5task-train.pt` and `5task-val.pt` files are the train/validation latent statistics for the 5-task data. They can also be regenerated by extracting latents first; the extraction output directory will contain `latents_stats.pt`.

## Latent Extraction CSV

The latent extraction CSV must include a header row and three columns:

```csv
input_path,gt_path,label
/path/to/degraded_0001.png,/path/to/clean_0001.png,0
/path/to/degraded_0002.png,/path/to/clean_0002.png,1
```

- `input_path`: path to the degraded/input image.
- `gt_path`: path to the clean ground-truth image.
- `label`: an integer metadata label used by the extraction pipeline. It is included for convenience when building latent shards and is not required at inference time; SLAIR does not require degradation labels for restoration inference. If you use CSV-based training utilities in this repository, keep this third column for dataloader compatibility, even if the values are dummy/non-semantic ids.

## Inference

Inference also uses extracted latent folders. First prepare a CSV for each test set with the same `input_path,gt_path,label` format, then extract latents:

```bash
bash run_extraction.sh \
  tokenizer/configs/vavae_f16d32.yaml \
  /path/to/Rain100L.csv \
  /path/to/latent_output \
  Rain100L
```

This creates `/path/to/latent_output/Rain100L_512/`. Run restoration on one extracted latent dataset:

```bash
bash run_inference.sh \
  configs/lightningdit_xl_vavae_f16d32.yaml \
  --data_path /path/to/latent_output/Rain100L_512
```

Run multiple extracted datasets by repeating `--data_path`:

```bash
bash run_inference.sh \
  configs/lightningdit_xl_vavae_f16d32.yaml \
  --data_path /path/to/latent_output/Rain100L_512 \
  --data_path /path/to/latent_output/BSD68_512
```

Or scan all extracted latent folders under one directory:

```bash
bash run_inference.sh \
  configs/lightningdit_xl_vavae_f16d32.yaml \
  --datasets_dir /path/to/latent_output
```

The inference script calls `batch_inference.py` through `accelerate`. Set `ckpt_path` to the Setting-II DiT checkpoint and `vae.fusion_ckpt_path` to the Setting-II decoder checkpoint in `configs/lightningdit_xl_vavae_f16d32.yaml` before running.

## Training

### 1. Train VAE

```bash
cd vavae
python train.py
```

Optional arguments:

```bash
python train.py \
  --config ./configs/train.yaml \
  --seed 42 \
  --logdir /path/to/logs/vae
```

Return to the project root before running the following steps:

```bash
cd ..
```

### 2. Extract Latents

Use the trained VAE/tokenizer config to extract paired latent features:

```bash
bash run_extraction.sh \
  tokenizer/configs/vavae_f16d32.yaml \
  /path/to/5-task_train.csv \
  /path/to/latent_output \
  5-task_train
```

The extraction script calls `extract_paired_features.py` and writes shards to:

```text
/path/to/latent_output/5-task_train_512/
|-- latents_rank00_shard000.safetensors
|-- latents_rank00_shard000_paths.json
`-- latents_stats.pt
```

Use the generated `latents_stats.pt` as `data.stats_path` in `configs/train.yaml`, or copy/rename it to a stable file such as `5task-train.pt`. Run the same command for validation data, for example with `5-task_val`, and set the result as `valid_data.stats_path`.

### 3. Train DiT Transport Model

```bash
bash run_train.sh configs/lightningdit_xl_vavae_f16d32.yaml
```

The DiT config controls the latent dataset paths, VAE settings, checkpoint path, output directory, transport objective, and sampling parameters.

### 4. Train Decoder

```bash
python train_decoder_dit.py
```

Optional arguments:

```bash
python train_decoder_dit.py \
  --config_path ./configs/train.yaml \
  --dit_ckpt_path /path/to/dit/checkpoint.pt \
  --save_dir /path/to/save/decoder
```
